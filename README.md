# 本地实时行情接入与窗口聚合（Python 骨架实现）

在 FastAPI 服务基础上，实现本地实时行情接入、去重、乱序归位、
结构演进、容量控制与窗口聚合；用本地文件模拟数据源日志与消费位点，
保证重复/乱序/结构变更/容量受限下聚合结果一致、失败原因可解释，
服务重启后已确认事件与聚合状态不重复、不丢失。

## 快速开始

```bash
uv sync
uv run python main.py          # 启动 HTTP 服务，数据写入 ./data
uv run pytest                  # 运行全部测试（-s 打印输入事件与判定依据）
```

## 代码结构

```
market_pipeline/
  model.py    事件/Ack/拒绝原因/窗口聚合模型与配置
  schema.py   schema v1/v2 校验与演进（新增字段缺省语义稳定）
  windows.py  固定窗口归位与可交换聚合
  storage.py  追加事件日志 + 原子快照 + 消费位点（本地持久化）
  engine.py   校验→去重→窗口→容量→持久化 的确定流水线
  api.py      FastAPI 路由
tests/        去重/乱序/结构演进/容量/持久化/并发/HTTP 测试
docs/DESIGN.md 事件模型、去重与窗口规则、兼容策略与验证方法（详细文档）
```

详细规则与验证方法见 [docs/DESIGN.md](docs/DESIGN.md)。

## 主要能力

- 多来源行情按标的归入固定时间窗；同 `(source, event_id)` 重复提交幂等不重复计入。
- 乱序/迟到事件按「事件时间 + 水位线 + 迟到容忍」确定归位或明确拒绝，不静默丢弃。
- schema v1→v2 向后兼容，新增 `trade_side` 缺省稳定为 `unspecified`；
  字段缺失、类型不符、版本未知、窗口越界分别给出可区分原因，原始载荷可重投。
- 单窗/全局/批量三级容量策略，拒绝原因可区分；写入串行化，并发结果确定。
- 事件日志 + 原子快照 + 位点文件，重启后从快照恢复（或日志重放），不丢不重。
